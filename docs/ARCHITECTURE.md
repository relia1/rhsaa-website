# Architecture & conventions

The target architecture for the RHSAA rewrite. Every agent and contributor follows this file.
If a change needs to break a convention, update this file in the same change and note why in
`docs/DECISIONS.md`.

## Stack

| Concern     | Choice                                                                       |
| ----------- | ---------------------------------------------------------------------------- |
| Framework   | Astro 7 (static output, `build.format: 'directory'`)                         |
| Language    | TypeScript, `astro/tsconfigs/strict`                                         |
| Styling     | Tailwind CSS v4 via `@tailwindcss/vite`; tokens in `src/styles/global.css`   |
| Content     | Astro content collections (`src/content.config.ts`) with Zod schemas         |
| Images      | `astro:assets` (`<Image>` / `<Picture>`) from `src/assets/`; never `public/` |
| Package mgr | Bun (`bun install`, `bun run <script>`)                                      |
| Formatting  | Prettier + `prettier-plugin-astro` + `prettier-plugin-tailwindcss`           |
| Checks      | `astro check`, `scripts/lint-conventions.mjs`, `check-links`, `parity`       |

No client framework (React/Vue/Svelte) is needed: the legacy site's only interactivity is the
nav dropdowns and mobile menu. Use small `<script>` tags in Astro components (or `<details>`)
instead of jQuery/Bootstrap JS. Add a framework only after recording the reason in `DECISIONS.md`.

## Directory layout

```text
legacy/                 READ-ONLY source of truth. Never edit, move, or import from it at runtime.
migration/
  status.json           Per-route tracker (todo | in-progress | migrated | verified | dropped)
  legacy-audit.json     Generated by `bun run legacy:audit`
  parity/<slug>/        Generated parity reports + screenshots (gitignored)
  briefs/<slug>.md      legacy-analyst migration briefs (gitignored working files)
  reviews/<slug>.md     parity-reviewer verdicts, saved verbatim (committed; evidence for `verified`)
scripts/                Node helpers used by humans and agents (see CLAUDE.md)
src/
  assets/               Images imported through astro:assets, mirroring legacy/images/<folder>/
  components/           Reusable UI (PascalCase .astro). Layout chrome in components/layout/
  config/
    site.ts             Site-wide constants: name, nav, social links, emails, address,
                        PayPal button ids, Mailchimp ids. Single source — never inline these.
    redirects.mjs       Legacy URL -> new URL redirects (imported by astro.config.mjs)
    unlisted.mjs        Published-but-unlisted routes (noindex, no inbound links, no sitemap)
  content/              Collection entries (Markdown / YAML / JSON), one folder per collection
  content.config.ts     Collection definitions + Zod schemas
  layouts/
    BaseLayout.astro    <html>, <head> (SEO meta), Header, Footer, <main> slot
    PageLayout.astro    BaseLayout + Hero + standard content width
  pages/                Routes. Thin: query content, compose components. No large copy blocks.
  styles/global.css     Tailwind import + @theme design tokens
public/                 Files served verbatim: favicons, PDFs (public/pdf/), robots.txt
```

## Routing & URLs

- **Keep legacy URLs.** `/about/sota`, `/volunteer/biowriter`, `/grants/` etc. stay the same.
  A route maps 1:1 to its legacy file unless `migration/status.json` gives a different `target`.
- If a URL changes, add an entry to `src/config/redirects.mjs` in the same change.
- Internal links are root-absolute (`/about/board`), never relative (`../about/board`).
- Repeated detail pages come from a collection + dynamic route, e.g.
  `src/pages/volunteer/[slug].astro` with `getStaticPaths()` over `volunteerRoles`.
- Legacy `*.html` URLs (`/about/sota.html`) and the build output format depend on the host:
  open question in `DECISIONS.md`; see `MIGRATION_PLAN.md → Phase 5`. Don't add `*.html` keys
  to `redirects.mjs` meanwhile.

## Content model

Content lives in collections, not in page markup, whenever the legacy page repeats a structure
(cards, lists of people, yearly records). Planned collections (schemas are designed in Phase 1):

| Collection              | Loader / format                                  | Legacy source                                       |
| ----------------------- | ------------------------------------------------ | --------------------------------------------------- |
| `volunteerRoles`        | glob, Markdown                                   | `volunteer/*.html` (25 role pages; see below)       |
| `board`                 | file, YAML                                       | `about/board.html`                                  |
| `committees`            | glob, Markdown                                   | `about/committees.html`                             |
| `sotaReports`           | glob, Markdown per year                          | `about/sota.html`, `sota2024.html`, `sota2025.html` |
| `grants`                | file, YAML                                       | `grants/grantrecipients.html` (by fiscal year)      |
| `scholarshipRecipients` | glob, Markdown                                   | `scholarships/pastrecipients.html` (by class year)  |
| `principals`            | file, YAML                                       | `history/principals.html` (by school)               |
| `princesses`            | file, YAML (+ Markdown for current year feature) | `history/princesses.html`                           |
| `events`                | file, YAML                                       | `events/*.html` (picnic, reunions, board meetings)  |
| `links`                 | file, YAML                                       | `links/index.html`                                  |

`volunteerRoles` covers 27 tracker routes: the 25 role pages, rendered by
`src/pages/volunteer/[slug].astro`, plus two listing pages that are not entries:
`/volunteer/` (public roles) and `/volunteer/restricted` (restricted roles; unlisted).

Schema rules:

- Every image field uses the `image()` schema helper so it is validated and optimised.
- Every image has required `alt` text. Legacy pages often have none (or only `title`) — write
  factual alt text from the surrounding copy; never invent details.
- Dates are `z.coerce.date()`; money is a number of dollars; years are numbers.
- Ordering is explicit (`order` field or a date), never "file order".
- Visibility flags (`visibility: public | restricted | unlisted | draft`) instead of deleting
  pages. Volunteer roles: `public` → listed on `/volunteer/`; `restricted` → listed on
  `/volunteer/restricted`; `unlisted` → only reachable by URL. Routes with `unlisted`
  visibility must also be in `src/config/unlisted.mjs` (and vice versa).

## Copy fidelity

- Legacy copy is migrated **verbatim** — same words, same names, numbers, emails and dates.
  Only fix: encoding mojibake (`�` → proper `’ “ ” –`), doubled spaces, and broken HTML.
- Do not "improve" wording, merge paragraphs, or drop sentences. Typos in legacy copy are
  recorded in the page's status notes for the owner to approve, not silently fixed.
- `bun run parity <route>` fails if any legacy sentence is missing from the new page.

## Styling

- Tailwind utilities in markup. No new global CSS except tokens and `@layer base` element defaults.
- Tailwind scans only `src/` for class names (`@import 'tailwindcss' source('..')` in
  `global.css`), so legacy markup and docs don't leak utilities into the built CSS.
- Use tokens (`text-gold`, `bg-mist`, `bg-slate`, `font-display`) — never raw hex values.
- Mobile-first. The legacy breakpoints (Bootstrap 4: 576/768/992/1200) map to Tailwind
  `sm/md/lg/xl` closely enough; don't add custom breakpoints.
- The rewrite should be **recognisably the same site** (gold on white, Playfair Display, photo
  heroes with white title, grey rounded content blocks, gold callouts) but cleaned up — it is
  not a pixel-perfect copy, and not a redesign. Design changes beyond that need owner approval.

## Components (reuse everywhere)

Built in Phase 0 (`bun run status` checks these): `BaseLayout`, `PageLayout`, `Header`
(desktop dropdowns + accessible mobile menu), `Footer`, `Hero` (image + title; replaces the 28
`.photo*` CSS classes), `Section` (heading + gold rule), `Callout` (gold `.helpbox`), `Card`,
`CardGrid`, `BackLink`.

Built with the first page that needs them: `QuickLinks` (home), `PersonCard` (board,
principals, recipients), `PayPalDonateButton` (donate), `MailchimpSignup` (contact),
`YouTubeEmbed` (memorials).

Before creating a component, search `src/components/` — extend an existing one instead of
duplicating it.

## Third-party embeds (must keep working exactly)

| Page                               | Embed                        | Rule                                              |
| ---------------------------------- | ---------------------------- | ------------------------------------------------- |
| `/contact/`                        | Mailchimp signup form + JS   | Same `action` URL, field `name`s, hidden honeypot |
| `/news/`                           | Mailchimp archive `<script>` | `<script is:inline src=...>`                      |
| `/donate/`, `/donate/megansletter` | PayPal hosted button         | Same `hosted_button_id` values, from `site.ts`    |
| `/history/memorials`               | YouTube iframe               | `title` attribute, lazy loading, responsive 16:9  |

IDs live in `src/config/site.ts`.

The Mailchimp signup embed loads `mc-validate.js`, which bundles jQuery, plus an inline script
that calls `jQuery.noConflict` — this conflicts with "no jQuery" (AGENTS.md rule 3). Open
question in `DECISIONS.md`; until it's decided, don't rewrite or drop that script.

## Fonts

Playfair Display is **self-hosted** (owner decision) through Astro's Fonts API with the local
provider, reading the woff2 files from `@fontsource-variable/playfair-display` — builds need no
network and no request ever goes to Google Fonts.

- Configured once in `astro.config.mjs → fonts` (`cssVariable: '--font-playfair'`, variable
  weight 400–900, normal + italic, Latin + Latin-ext via `unicode-range`).
- `BaseLayout` renders `<Font cssVariable="--font-playfair" preload={[{ style: 'normal' }]} />`
  in `<head>` — copy it from the placeholder `src/pages/index.astro`.
- Components use `font-display` / `font-body` utilities (tokens in `global.css`), never a
  font-family string. Don't add `<link>`s to fonts.googleapis.com or any other font CDN.
- Legacy only loaded weight 400 and faked bold; the variable font gives real 700 for `<b>`.

## Unlisted pages

Owner decision: the 9 pages that legacy never linked (and `/volunteer/restricted`, which
legacy hides on purpose) stay **published but unlisted**. The list is
`src/config/unlisted.mjs`. For every unlisted route:

- render `<meta name="robots" content="noindex">` (BaseLayout does this automatically via
  `isUnlisted(Astro.url.pathname)` — don't hand-roll it per page);
- no link to it from any listed page: nav, footer, listing pages, or any page not in
  `unlisted.mjs`. Unlisted pages keep their legacy links, including to each other (owner
  decision 2026-10-20), e.g. role pages back to `/volunteer/restricted`;
- excluded from the sitemap (handled by the sitemap `filter` in `astro.config.mjs`).

`bun run links` fails if any of these is violated. A legacy link from a listed page to an
unlisted one is not migrated; it's an open question (`DECISIONS.md`). To change a page's
status, edit `unlisted.mjs` (and the collection's `visibility`) and record it in
`docs/DECISIONS.md`.

## Accessibility & SEO baseline (every page)

- Exactly one `<h1>`; heading levels do not skip.
- `<html lang="en">`, a `<title>` matching legacy (`<Page> - Roosevelt High School Alumni
Association`) and `<meta name="description">`. Legacy repeats some titles; keep them until the
  owner decides (`DECISIONS.md → Open questions`).
- All images have `alt` (empty `alt=""` only for decorative images).
- Nav is keyboard operable; dropdowns open on focus/click, not hover only.
- Colour contrast: gold `#a99533` on white is 2.99:1 — it fails WCAG AA even for large text.
  On white, use gold only for decoration (rules, borders, text-shadowed banner title over a
  photo) and use ink for text/links. Gold text is fine on black (7.0:1). On slate it is 3.08:1:
  large text only (≥ 24 px, or ≥ 18.66 px bold). Black on `mist` is 13.5:1; white on slate
  is 9.2:1. Raise this with the owner if a page needs gold text on white.
- External links that open new tabs use `rel="noopener"`.
